# Ask Oracle to explain an authorised saved search

**Audience:** CFOs and analysts  
**Oracle release:** 2026.2 August  
**Status:** Scripted tutorial; not verified in a live NetSuite tenant  
**Risk classification:** read-only

## Why this matters

Your saved search can become a plain-English finance briefing without building a new dashboard. This walkthrough uses Oracle's published capability and focuses on reducing repetitive professional-services setup or training work. It does not replace complex design, security or audit assurance.

## Before you begin

Confirm NetSuite Next / Ask Oracle availability and role access; identify an existing accessible saved search. Access and UI vary by account and role. Use a sandbox or authorised non-sensitive training data; do not share credentials or customer data.

## Step-by-step administrator/user workflow

1. Confirm Ask Oracle has been enabled for the role; availability may be phased.
2. Find a saved search you already have permission to access.
3. Reference the exact saved-search title or script ID in an Ask Oracle question.
4. Ask for a summary, an explanation of the filters used, and any limitations.
5. Reconcile totals and filters against the saved search displayed in NetSuite.
6. Avoid acting on financial outputs until an accountable reviewer checks the numbers.

## What good looks like

Reproducible prompt and source-check method for a saved-search summary. Ask the user to save an evidence reference, timestamp, applicable role and unresolved blocker in a private location.

## Troubleshooting

If menus or tools are unavailable, first check account release, feature entitlement, role access and the latest Oracle instructions. Do not escalate privileges without administrator approval. If the outcome differs from NetSuite, treat NetSuite source records as authoritative and stop before further actions.
